# Blog Cover Image

## Workflow

1. 대상 글을 먼저 읽는다.
   - frontmatter의 `title`, `description`, `tags`, `series`, `seriesOrder`, 기존 `cover`, `coverAlt`를 확인한다.
   - 본문 도입부와 핵심 섹션을 읽고 이미지로 형상화할 주제를 1문장으로 정리한다.

2. 기존 커버와 최근 생성 이미지를 확인한다.
   - `public/covers`의 유사 주제 이미지를 확인한다.
   - 같은 캐릭터, 같은 팔레트, 같은 구도, 같은 소품이 반복되지 않게 한다.
   - 특히 이전 이미지의 문제였던 "로봇 캐릭터 반복", "어두운 네온 테크 아트", "같은 URL에 덮어쓰기"를 피한다.

3. 이미지 방향을 정한다.
   - 기본 비율은 `16:9`다.
   - 주제마다 다른 캐릭터와 색감을 고른다.
   - 캐릭터 예시는 올빼미, 아홀로틀, 거북이, 고양이, 문어, 작은 정령, 우편배달 동물, 장난감 기계 등이다.
   - 글의 기술 개념은 장면으로 바꾼다. 예: 타입 안전성은 정리된 카드/도장, 런타임 변환은 관찰 장치/파이프, 비교는 지도/분기 경로.

4. 이미지 생성 프롬프트를 작성한다.
   - 사용자가 명시적으로 이미지 생성을 요청했을 때만 이미지 생성 도구를 쓴다.
   - 프롬프트에는 subject, layout, style, palette, constraints를 구체적으로 넣는다.
   - 금지 요소를 명시한다: readable text, real code, logos, brand marks, people, generic AI tech art.
   - 기존 이미지와 달라야 할 때는 "no robot", "no desk", "no dark navy", "no paper texture"처럼 겹치는 요소를 직접 제외한다.

5. 파일을 적용한다.
   - 생성 이미지는 `public/covers/<slug>-<distinctive-token>.png`처럼 의미 있는 새 파일명으로 둔다.
   - 기존 커버를 교체할 때도 같은 파일명에 덮어쓰지 않는다. 브라우저와 Next/Image 캐시 때문에 화면에서 바뀌지 않아 보일 수 있다.
   - 마크다운 frontmatter에 `cover`와 `coverAlt`를 추가하거나 갱신한다.
   - `coverAlt`는 한국어로 장면과 글 주제를 짧게 설명한다.

6. 검증한다.
   - `ReadFile`로 새 이미지 파일을 열어 실제 결과를 확인한다.
   - `rg`로 오래된 커버 경로가 남아 있지 않은지 확인한다.
   - `ReadLints`로 수정한 마크다운 진단을 확인한다.
   - 사용하지 않는 이전 커버 파일은 이번 작업에서 만든 파일일 때만 삭제한다.

## Quality Bar

- 커버는 글의 주제를 설명해야 한다. 예쁘기만 한 장식 이미지는 피한다.
- 시리즈 글도 지나치게 통일하지 않는다. 글마다 다른 캐릭터, 색감, 구도를 우선한다.
- AI 이미지 특유의 번쩍이는 네온, 추상 회로, 의미 없는 코드 조각, 반복되는 귀여운 로봇을 기본값으로 쓰지 않는다.
- 화면에서 바뀌지 않는다는 피드백이 나오면 먼저 파일 URL 캐시 문제를 의심하고 새 파일명으로 바꾼다.
